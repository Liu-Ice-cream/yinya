# 静态网站部署

音芽运行在浏览器中，创作、存储及音频导出使用本地能力，不需要音频服务器。当前尚未发布公开在线演示。

## 生成网站包

需要 Node.js 24 和 npm。在项目目录执行：

```sh
npm ci --ignore-scripts
npm run package-yinya
```

输出目录为 **`build/yinya-site/`**，其中 `index.html` 为首页。网站包仅包含音芽界面、合成器构建文件、独立 MP3 编码器和许可证，保留必要的源码映射。重复运行会替换这个生成目录。

GitHub Actions 的主分支检查通过后，也可从对应运行的 Artifacts 下载 `yinya-site`，解压后使用。包内的 `vendor/`、`notices/` 和 `license.txt` 必须一起分发。

## 托管配置

将网站包内的文件部署到静态网站托管服务。可以放在网站根目录，也可以放在固定子目录中；保持目录层级，访问带末尾 `/` 的入口地址。

- 使用 HTTPS，本地调试可使用 localhost。
- `.js` 文件需返回 JavaScript MIME 类型，允许同源模块脚本及模块 Worker。
- 缺失的脚本应返回 404，避免将所有资源路径重写为首页 HTML。
- 发布后刷新检查页面；更新时同步发布首页、脚本、样式与编码器，避免混用不同构建。

只部署 `build/yinya-site/`，整个仓库和上游 `website/` 不是音芽的部署目录。

## 发布验收

1. 在公开地址打开首页，三个起步作品和四声部正常显示。
2. 点击音符试听，再循环播放；小节跟随、手动查看与恢复正常。
3. 保存作品并刷新，验证恢复；下载 JSON 备份并重新导入。
4. 在另一个浏览器打开分享链接，确认作品内容一致。
5. 导出并下载 WAV 与 MP3，确认编码器及 Worker 没有加载错误。
6. 打开页脚的 MIT 和开源组件说明，检查所有许可链接。

作品库属于当前网站地址。更换域名、协议或端口前，先在旧地址下载 JSON 备份，再在新地址导入；部署不会自动迁移已有本地作品。
