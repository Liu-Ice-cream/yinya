# 产品范围与后续方向

音芽帮助不懂编曲的人，通过旋律、和弦、贝斯与鼓点完成一段自己的音乐。重点是容易开始、操作有声音反馈、作品可以留下和分享。

## 已完成

- 4／8／16 小节、四声部的简化创作界面，原创起点与音阶限制。
- 追加空白或重复扩展、按四小节分组导航、整段复制四声部，缩短/覆盖提示与撤销恢复。
- v2 作品格式兼容读取旧 v1 草稿、作品、分享链接和 JSON 备份。
- 点击音符即时试听、循环播放、播放小节自动跟随与手动查看。
- 撤销/重做、本地作品、链接分享改编、JSON 备份。
- WAV 与 MP3 本地导出。
- 旋律 1／2／4／8 格时长、连续长音显示、选中调整与删除、边界自动收短；v3 格式兼容旧 v1／v2 短音。
- 六款旋律音色、当前四小节旋律试听；自然收尾与整段循环导出；v4 格式兼容旧 v1／v2／v3。

## 近期重点

- 收集初次使用者的反馈，改善引导和手机操作。
- 增加实体手机、多浏览器与长期循环验证。
- 建立可直接打开的在线演示，保持保存范围与分享提示清楚。

## 后续候选

- 扩展至 32 小节，先验证手机上的长曲导出内存和耗时。
- 段落命名、重新排序与曲目结构。
- 更多原创起点与音乐积木组合。
- 乐器音色与演奏表现：继续收集六款音色的设备试听反馈，评估力度及各声部独立选音色，详见下方前瞻。
- 贝斯长音、旋律跨小节延音与力度；当前长音限于旋律的单个小节。

v0.2.0 已扩展到十六小节，继续保持每次编辑一小节的简单操作。以上方向不代表交付日期承诺；账号、云端社区及多人协作尚未纳入近期范围。

### 2026-10-10 可行性分析与基线限制

加入乐器风格的合成音色可行性高，主要工作是接入预设、调校音量和演奏参数，以及维护作品兼容性。现有 BeepBox 引擎已经支持 FM、谐波、拨弦等合成类型；仓库的 `editor/EditorConfig.ts` 含 grand piano、electric piano、nylon guitar、steel guitar、clean guitar 等预设。

音芽目前的限制主要在简化界面和作品转换层：

- `website/yinya/index.html` 只提供三角波、圆润波形和方波，且只为旋律开放选择。
- `yinya/model.js` 的 `validate()` 只认可三个波形标识，`songJSON()` 将旋律、和弦、贝斯固定转换为 chip 乐器。仅增加菜单选项不能接入新合成类型。
- 旋律和贝斯使用八个五声音阶音高，每个格子固定为一个十六分音符；相邻格子是独立发音。缺少可编辑的长音、力度和连音，会限制钢琴、吉他的表现力。
- 点击试听与完整播放均复用 `songJSON()`，WAV / MP3 也由同一作品转换入口生成，有利于保持声音一致。不过当前试听只有 0.32 秒，完整导出严格截止于作品长度，新增衰减和混响后需要重新处理余音。

上述判断基于源码检查，尚未对候选预设完成试听、音量校准或实体手机性能验证。预设名称说明它试图表现的乐器，不保证达到真实录音的质感。

### 推荐的声音路线

第一阶段优先使用现有合成引擎，不引入大型采样音源。电子琴是一个宽泛类别，可具体拆成电钢琴、风琴和合成器主音，便于用户理解差别。

- 钢琴：使用现有钢琴预设作为起点，目标是清晰的起音与自然衰减。接入难度中等，真实感需要实际试听判断。
- 电钢琴：从 FM 或谐波预设挑选，适合柔和旋律与伴奏。接入难度较低至中等，和现有合成架构匹配。
- 木吉他：从尼龙弦或钢弦预设挑选，目标是拨弦感。接入难度中等，和弦扫弦及自然延音作为后续演奏能力。
- 清音电吉他：现有预设可作起点，先验证旋律可辨识度，再考虑失真、滑音等演奏效果。
- 合成器主音：用于电子与游戏风格，与现有合成能力匹配；保留原有三个波形以兼容旧作品。

首轮可以以八种音色为试听候选：保留三种旧声音，新增上述五种。最终数量和名称以听感验证为准，不把整个 BeepBox 预设库直接展示给初学者。选音色时提供同一短句的试听，并对感知音量作校准，减少“更响所以更好听”的误判。

若之后希望达到更接近真实钢琴或吉他的效果，可再评估采样路线。需要额外解决音源授权与再分发、资源下载和离线缓存、手机内存、多音高与力度层、资源版本，以及实时播放和离线导出使用同一音源的问题。BeepBox 当前乐器配置不是通用采样器接口，不能将音频文件直接作为新预设塞入；这属于更大的声音架构改进，工作量显著高于接入合成预设。

### 分阶段改进

1. **精选旋律音色**：统一乐器注册表，使用稳定 ID 和固定预设修订，接入约八种候选声音；保持作品的音符内容不变。先开放旋律选择，保留旧作品的原始声音。
2. **增加演奏表现**：支持跨格子的长音和少量力度档，处理发音衰减与余音；随后让和弦、贝斯独立选择适合的音色，并增加鼓组组合。默认仍为易用模式，完整半音阶或更大音域作为可选进阶能力。
3. **评估更真实的声音**：根据试听反馈决定是否需要采样器；多乐器叠加、同一轨道按段换音色等功能另行评估，避免第一阶段同时改变轨道结构。

作品数据应把音符内容与乐器选择分开。现有全局 `voice` 可迁移为各轨道的 `instrumentId`；是否升级作品版本，需要与长音、力度的数据结构一起决定。未知或已移除的 ID 应提示并使用明确的兼容声音，不能静默重写原存档。预设参数不要直接塞入分享链接；稳定 ID 配合预设修订可控制链接体积，并减少更新后旧作品听起来不同的问题。

`EditorConfig.ts` 同时含浏览器环境判断，不宜直接作为需要在 Node 测试或未来音频 Worker 中使用的运行时模块。宜提取经过筛选的纯数据音色定义，保留上游署名与许可说明，由统一转换函数生成各类乐器配置，并保留预设中的包络、衰减和效果参数。

### 后续实施验收重点

- 同一短句在候选音色中能听出清楚区别，切换音色不会改变音符与长度；切换可撤销。
- 点击试听、完整播放、WAV 与 MP3 使用同一乐器定义；试听时长足以表现所选乐器。
- 旧 v1 / v2 作品、分享链接和备份保留原始波形；新音色在保存、导入及分享后保持一致。
- 对长音、重复起音、混响和最后一个音的余音制定明确行为；导出区分严格循环长度与带余音结束，避免最后一音被突然截断。
- 在实体手机上验证 16 小节、四声部同时播放及导出的流畅度，测试不同乐器的响度与削波情况。
